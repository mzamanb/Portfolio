Problem + solution

// locked — do not revisit

Problem statement

AI has made it easier to generate code but more important to understand it. The next generation uses AI daily but cannot debug it, fix it, or build without it. Every platform teaches in a browser sandbox — none teach in a real IDE. 87% of learners quit before finishing anything. Not because coding is hard — because nobody built the bridge between wanting to learn and actually building something real. The gap between learning and doing is where everyone quits.

Solution statement

Mentor — a desktop learning platform that lives inside VS Code. Real IDE from lesson one. Plain English analogies before every concept. A context-aware AI tutor that reads your actual file. Every lesson ends with something that exists. One project, start to finish, per course. The bridge between wanting to learn and actually building.

The 4 gaps competitors miss

1. Nobody teaches real IDE setup

Codecademy, Scrimba, freeCodeCamp all teach in browser sandboxes. The Odin Project uses real IDE but drops beginners in with zero guidance.

2. Content is written for people who already think like developers

Even "beginner" courses assume technical framing. No real-world analogies. Jargon without explanation.

3. The UI is ugly or sterile

freeCodeCamp and Odin look like 2015 documentation. For a 13+ audience, first impressions determine whether they stay.

4. AI is bolted on, not built in

Existing AI features are generic chatbots. They do not know the learner's file, current step, or specific mistake.

Positioning

Not another coding course. Not gamified with streaks and badges. Not a career path to a developer job. The bridge — from curious to capable. One project at a time. For the generation that grows up with AI and needs to understand it, not just use it.

Architecture

// three surfaces · one source of truth · no backend in v1

Surface 1

VS Code panel

Primary learning surface. Webview HTML/CSS/JS. postMessage bridge.

Surface 2

Dashboard

Browser web app. Progress, courses, projects. Realtime live updates. URI launch.

Surface 3

CLI — mentor

npm global. mentor start / next / status / hint / validate / doctor. Reads local state.

Source of truth — two files

courses.json

All course content — lessons, steps, analogies, code, win_conditions, terminal commands, AI system prompts, common mistakes, design preview URLs. Ships with extension. Adding a course = filling the template. No UI code changes.

progress.json

Learner state — current course, lesson, step, completed steps. Local first, syncs to Supabase. Works offline. All three surfaces read and write this.

Extension host — what it owns

File watcher

Triggers on every save. Reads file, passes to validation engine with current step win_condition.

Terminal watcher

Reads stdout/stderr. Detects 20+ known error patterns. Maps to plain English in panel. Never runs commands for the learner after Course 01.

Validation engine

Checks file against win_condition rules. Pass → step unlocks, progress.json updates, panel advances. Fail → AI tutor triggered with file + step + error context.

Project scaffolding

Creates folder structure on "Start course." Shows every command it ran. Plugin does it once on first encounter, learner does it themselves from Course 02.

Resume detection

On VS Code open: reads progress.json, shows "Resume Course 03 · Step 3?" One click. Opens panel at exact right step.

AI tutor — Claude API

Context on every call

Current file content + current step + failed win_condition + course system_prompt + common_mistakes for this step. Never generic.

Hint budget

Free tier: 5 hints per lesson. Pro: unlimited. Auto-triggered on validation fail. Manual via Hint button in panel or mentor hint in CLI.

Backend — Supabase

Tables

users · progress (upsert on step complete) · events (append-only) · courses (mirrors courses.json for dashboard reads)

Supabase Realtime

Dashboard subscribes to user's progress channel. Step complete in VS Code → Supabase write → Realtime broadcast → dashboard updates within milliseconds.

Event schema

id · user_id · event_type · course_id · lesson_id · step_id · surface (plugin|cli|web|mobile) · metadata (jsonb) · created_at. Types: session_start, lesson_opened, step_attempted, step_complete, step_failed, ai_tutor_triggered, terminal_error, course_complete, project_shared, session_abandoned.

URI launch — dashboard to IDE

vscode://mentor.extension/open?course=03&lesson=1&step=3

Dashboard "Continue" fires this URI. VS Code registers the handler. Extension opens panel at exact step. mentor-daemon (system tray Node process) handles when VS Code is closed.

CLI — full command list

mentor start     // resume current course at last step
mentor next      // advance after validation passes
mentor status    // show current progress
mentor hint      // request AI hint (counts against budget)
mentor validate  // manually trigger step validation
mentor doctor    // check Node, npm, VS Code, extension
mentor sync      // force sync local progress to cloud
mentor reset     // reset current step files only
mentor courses   // list all courses and lock status
mentor course 03  // jump to specific course
mentor projects  // list completed projects
mentor new       // scaffold project folder + files
mentor open      // open current project in VS Code
mentor login     // authenticate with platform
mentor whoami    // show current user + active course
mentor help      // show all commands

Success metrics

// measure outcomes, not engagement

North star

% of learners who complete Course 06 and share their project with at least one person. Target: 40%. This captures completion AND pride. If this is high, every other metric follows.

Leading indicators — early signals

Course 01 completion rate

Target: 70%. Plugin event: learner runs code . and Live Preview opens. Below 50% = setup friction is killing the product.

Lesson-to-lesson drop rate

Target: less than 15% drop per lesson. Spike at any lesson = content is too hard, too confusing, or too boring.

AI tutor usage rate

Watch: not too high (content unclear), not too low (learners quitting silently). Sweet spot: 1–2 questions per lesson.

Time to first win

Target: under 45 minutes from first plugin activation to first Live Preview open. Over 90 min = most people quit before the hook lands.

Course 03 → 04 continuation

Target: 60%. First significant complexity jump. Below 60% = difficulty curve too steep, needs a bridge lesson.

Lagging indicators — business health

Free → Pro conversion

Target: 8%. Measured within 7 days of Course 06 completion. Below 5% = paywall timing or Pro value is wrong.

Monthly churn

Target: under 5%. Above 8% = Pro content isn't delivering enough value.

Referral rate

Target: 1 referral per 5 completions. This is the growth engine. If low: project isn't impressive enough or no easy sharing mechanism.

MRR target

$3.2K by month 12 (400 Pro × $8). Not the goal — the consequence of the product working.

Vanity metrics — do not optimise for these

Total signups · Daily active users · Time on platform · Social media followers · App store rating average. These measure marketing and engagement, not whether the product delivers on its promise.
